Image Audit — Definitions & Fixes

What each check means and how to fix it. Issues are grouped by priority.

Critical

Load fail

The image fails to load, returning a non-200 HTTP status (for example 404 Not Found or 403 Forbidden). A broken image hurts both users and crawlers.

Fix: Correct the src URL or restore the missing file. Also check that paths inside srcset contain no spaces, which can break loading.

Missing / empty src

The <img> has no src attribute, or the src is empty, so no image is shown.

Fix: Give every content image a valid src. If the image is loaded via a framework, make sure the value is populated before render.

Alt text

The alt attribute is missing, empty, or longer than your configured limit. Alt text describes the image for screen readers and search engines.

Fix: Add concise, descriptive alt text (keep it under your max, e.g. ~125 characters). For purely decorative images, use an empty alt="" so assistive tech skips them.

Missing width

The image has no width attribute, so the browser can't reserve space before it loads.

Fix: Set an explicit width (together with height). This reserves layout space and prevents Cumulative Layout Shift (CLS).

Missing height

The image has no height attribute, so the browser can't reserve space before it loads.

Fix: Set an explicit height (together with width), or define an aspect-ratio in CSS, to avoid layout shift.

Rendered size

The image's displayed (rendered) dimensions differ from its real (natural) dimensions — you may be shipping far more pixels than are shown.

Fix: Export the image close to its displayed size, and use a responsive srcset with sizes so each device downloads an appropriately sized file.

Aspect ratio

The rendered aspect ratio differs from the source image's aspect ratio, which stretches or squashes the image.

Fix: Keep the displayed width:height matching the source, or use object-fit: cover / contain to fit without distortion.

File size

The image file is larger than your configured limit, slowing the page down.

Fix: Compress the image, resize it to the dimensions actually used, and prefer next-gen formats (WebP/AVIF) which are much smaller at the same quality.

No 2x

No high-resolution (2x/3x) variant is provided, so the image can look soft on retina / high-DPR screens.

Fix: Provide a srcset with density descriptors, e.g. image.jpg 1x, image@2x.jpg 2x.

Warning

Next-gen format

The image is not served in a modern format (WebP or AVIF), which are significantly smaller than JPEG/PNG.

Fix: Serve WebP or AVIF, using a <picture> element with fallbacks, or an image CDN that negotiates the format automatically.

Lazy loading

A below-the-fold image is not lazy-loaded, so it competes for bandwidth with content the user can already see.

Fix: Add loading="lazy" to off-screen images. Do not lazy-load the LCP / above-the-fold hero image — that one should load eagerly.

LCP preload

The Largest Contentful Paint image is not preloaded, so the browser discovers it late and the page feels slower.

Fix: Add <link rel="preload" as="image" href="…"> (or imagesrcset/imagesizes for responsive images) for the LCP image in the document head.

Info

LCP image

Identifies the Largest Contentful Paint image — the largest image visible above the fold. It is usually the most important image for perceived load speed.

Tip: Optimize this image first: load it eagerly, preload it, serve it in a next-gen format, and size it correctly.

Decoding

The LCP image does not use decoding="sync". For the main hero image, synchronous decoding can help it paint sooner.

Fix: Set decoding="sync" and loading="eager" on the LCP image so the browser prioritizes it.
